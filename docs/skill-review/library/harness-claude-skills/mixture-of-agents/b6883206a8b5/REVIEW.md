# Mixture-of-Agents Candidate Review

Disposition: retain as a candidate, but do not promote in its current combined
form. Proposed pack: `planning-orchestration`, optional and explicit-only. The
recommended execution is an in-session scout followed, only after a displayed
roster/time/quota confirmation, by bounded external proposer/refiner processes
and recorded aggregation. A single-model in-session plan is the default cheaper
alternative. The Flask control room is excluded from promotion pending its own
security boundary.

## Full-tree assessment

All 93 baseline files were reviewed in the six bounded passes recorded in
`EVIDENCE.md`: 7 entrypoint/metadata/prompt files, 13 Python orchestration and
adapter files, 9 schemas/tests, 9 Web UI Python files, 8 report/front-end files,
and 47 binary assets. Inventory provenance identifies one local Claude harness
tree with unknown upstream/version, no discovered license, and tree SHA-256
`b6883206a8b5a4743192f3ed4af13329f050d586a42d86291ba674e185bedb57`.

Retain the task-specific expertise: user-reviewed scout briefs, explicit paid
dispatch, phase checkpoints and targeted redispatch, full-broadcast refinement,
strict structured outputs, exact lineage pointers, stale-artifact suppression,
process-tree timeout handling, adapter-specific read-only controls, Git-visible
workspace mutation rejection, attachment containment, and deterministic
decision-map receipts. The visual/report assets are coherent and unchanged.

Required source-specific changes before promotion:

- Narrow discovery to explicit invocation and preserve the second confirmation
  after resolved roster, time, quota, and provider routes are shown.
- Replace measured-sounding planning-quality and equal-wall-clock claims with
  bounded design rationale unless candidate-specific evaluation supports them.
- Minimize parent tool authority and state precisely that planning approval
  authorizes `.moa/` artifacts, not implementation, publish, commit, deploy,
  credential access, provider login, or installation.
- Reverify every model identifier, CLI flag, authentication probe, permission
  policy, and structured-output behavior against current providers.
- Split the Flask UI from the skill or keep it strictly loopback-only until real
  non-loopback authentication, origin/CSRF defenses, narrower workspace roots,
  and paid-dispatch authorization exist.
- Establish redistribution permission. No discovered license means this copy is
  review evidence, not an approved reusable package.

## Validation and limitations

Static source inspection covered every baseline file and every graph coverage
gap. JSON schemas parsed, Python sources compiled without retained bytecode,
all 47 images decoded and hash-matched, and candidate contract validation is
reported in `EVIDENCE.md`. The candidate's offline suite passed 139/139 tests;
the repository inventory, review-contract, and local-candidate fixture suites
passed 13/13, 34/34, and 2/2 tests. Results and their limits are recorded in
`EVIDENCE.md` and the ticket ledger.

This was not a live MoA evaluation: no model/provider call, external research,
installer, server, or workflow ran. Mutation detection observes Git-visible
changes after a process and cannot prevent or roll back all side effects. Browser
profile isolation is not host authentication. Model diversity, plan quality,
latency, and cost claims remain unmeasured here. The same reviewer authored and
verified this review; no independent second-model assessment is claimed.

Promotion ends at human review readiness. It does not approve installation,
deployment, provider spend, live configuration changes, or implementation of a
generated plan. Open recommendations are indexed as
`Q-mixture-agents-invocation`, `Q-mixture-agents-claims`, and
`Q-mixture-agents-webui` in `EVIDENCE.md`.
