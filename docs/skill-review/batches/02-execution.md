# Engineering Execution Candidates

Scope: only these `pack-mattpocock` identities in the frozen inventory:
`code-review`, `diagnosing-bugs`, `implement`, `implement-spec`, `research`,
`resolving-merge-conflicts`, `tdd`, `git-guardrails-claude-code`, `handoff`,
`claude-handoff`.

Apply `RUBRIC.md` to every complete tree. Write per-candidate `REVIEW.md` and
`review.json`, with exact reviewed paths, source-specific changes, inline question
IDs, invocation/pack recommendations, execution alternatives, validation and
provider/update limitations. Inventory dependency and boundaries are documented
in `VERIFICATION.md` and `README.md`.

Prioritize exact endpoint versus merge-base review, staged/unstaged/untracked
implementation coverage, commit authority, optional bounded delegation rather
than mandatory recursive delegation, safe merge resolution, and actionable
review severity rather than compulsory heuristic churn. Preserve testing and
debugging expertise. Read scripts but do not run installers or hook mutations.

Acceptance requires full-tree review and independent driver verification. No live
changes, staging, commits, pushes, deployment or Herdr topology. Completion is
candidate readiness, not human approval.
