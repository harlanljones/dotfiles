# Hermes project rules — dotfiles

Hermes: when working in this repo, adopt this behavior. `AGENTS.md` (repo
root) is the operating manual — source-name conventions, run_* hook contract,
tool ownership, hard rules. This file adds Hermes-specific conduct; do not
duplicate it, layer on it.

## Session behavior

- Read `AGENTS.md` before your first edit in a session. It wins over ad-hoc
  requests when they conflict — surface the conflict instead of silently
  overriding it.
- Never apply or edit `dotfiles-showcase/` (independent submodule).
- Never commit secrets; new secrets go in `encrypted_*.age` files.
- `INDEX.json` / `INDEX.md` / the README tree are generated — regenerate with
  `python3 docs/generate_index.py` and `python3 docs/generate_readme_tree.py`
  after adding/moving/removing any tracked file; never hand-edit.
- Shell config goes in `dot_config/shell/`, never in `dot_bashrc`/`dot_zshrc`.
- Machine gating: vespasian is NOT augustus-lite — gate Omarchy-only files on
  `eq .machine "augustus"`, never on `eq .chezmoi.os "linux"`.
- After any `run_*` hook edit, remember `run_onchange_*` will re-trigger.
- Commits: use `dots push` (user-initiated); it never auto-commits agent work.

## Skill routing (Hermes skills — load with skill_view before the task)

Run Hermes for this repo via the repo-root **`./dev`** script. It is
idempotent: it creates the **dotfiles profile** (`hermes --profile dotfiles`),
prunes irrelevant skills via `skills.disabled`, bootstraps repo-local project
skills in `.hermes/skills/`, and ensures the repo is trusted — then drops you
into a session. Subcommands: `./dev setup` (bootstrap only), `./dev doctor`
(verify environment, including `chezmoi apply --dry-run`), `./dev -q "prompt"`
(one-shot; all other args pass through to hermes). The default profile keeps
the full catalog for everything else.

| Task in this repo | Load skill |
|---|---|
| Any chezmoi template, prefix, ignore, or apply question | `chezmoi-dotfiles` |
| Hyprland/Omarchy desktop config changes | `omarchy-hyprland-config` |
| Omarchy bar plugins / usage collectors | `omarchy-plugins` |
| New or edited `run_*` / shell scripts | `shell-portability` — bash targeting macOS + Linux |
| Executing an approved multi-task plan | `subagent-driven-development` |
| Plan interview before implementation | `grill-me` — invoked by the user, but expect it even after "go" |
| PRs / issues on the GitHub repo | `github` |
| Substantial autonomous/multi-step work | `unlazy` — keep working to verified done, no stubs |
| Research across platforms (web, docs) | `agent-reach` |
| age / 1Password secret setup (e.g. WSL SSH bridge) | `1password` |
| Hermes config/theming questions | `hermes-agent` |

Negative controls — do NOT load a skill for a near-neighbor ask:

- A one-line `.sh` fix in `dot_local/bin` ≠ `shell-portability` unless the
  script must run on all three machines (most do — when unsure, load it).
- Renaming a file's chezmoi prefix ≠ `chezmoi-dotfiles`? No — that IS the
  skill's domain; load it. But answering "what does `private_` mean" from
  AGENTS.md §2 needs no skill.
- Editing an existing theme template under `.chezmoitemplates/` ≠ theming
  work via `hermes-agent`; that skill is for Hermes's own theming.
- Doc/comment wording tweaks load no skill at all.

## Hooks (dotfiles profile)

Configured in `~/.hermes/profiles/dotfiles/config.yaml`, scripts in
`~/.hermes/agent-hooks/`:

- `dotfiles-git-guard.sh` — pre_tool_call on `terminal|execute_code`,
  fail_closed: blocks mutating git (push/pull/commit/merge/...); read-only
  git passes. Commit through the user or with explicit approval.
- `dotfiles-formatter.sh` — post_tool_call on `write_file|patch`: runs shfmt
  on edited `.sh`/`.bash`/`.zsh` files when shfmt is installed. Guarded no-op
  until shfmt is on PATH.
- `dotfiles-evidence.sh` — post_tool_call on `terminal`: appends a compact
  JSONL line per command to
  `~/.hermes/agent-hooks/dotfiles-evidence.jsonl`.
- `dotfiles-inject-git-status.sh` — pre_llm_call: injects branch + dirty-file
  status when the session cwd is inside this repo (matched on
  github.com/harlanljones/dotfiles).

First session start may prompt for per-profile hook allowlist consent, or
run `hermes --profile dotfiles --accept-hooks` once.

## Engineering gates (do these yourself, unprompted)

- After any template or hook edit: `chezmoi apply --dry-run` must succeed.
- After adding/moving/removing any tracked file: regenerate
  `INDEX.json`/`INDEX.md` and the README tree (CI gates both).
- Run `python3 docs/generate_index.py --check` before declaring template work
  done, and shellcheck any new shell script the way CI does.
